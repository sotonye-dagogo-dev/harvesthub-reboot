# Project AI Context

> **Overview:** HarvestHub (harvesthub-reboot) is an e-commerce marketplace web application connecting buyers and vendors. The codebase implements storefronts, product listings, vendor dashboards, a wallet system, and admin workflows. It's built with TypeScript using Next.js (App Router) for server + client rendering, Tailwind CSS + Ant Design for UI, and Prisma for data modeling; a mock in-memory data layer (in `lib/data`) is used during development.

## Key Modules

> **Section summary:** High-level areas where features and logic are implemented.

| Module | Location | Purpose |
|--------|----------|---------|
| Application routes & pages | `app/` | Server and client components, route groups: `(auth)`, `(buyer)`, `admin`, `vendor`, `signup`.
| API routes | `app/api/` | Route handlers for auth, products, orders, wallet, vendors, admin, banners, notifications, upload, reviews, vouchers.
| UI components | `components/` | Reusable UI and feature components used across pages and route groups.
| Libraries & services | `lib/` | Utilities, hooks, validation, mock data (`lib/data/database.ts`), stores and services.
| Prisma | `prisma/` | `schema.prisma`, seed script, and generated Prisma client (large generated files at build time).
| Docs & automation | `.ai-system/`, `.github/` | Agent docs, bootstrap commands, planning, and repository guidance.

## Notable Observations (from repomix build output)

> **Section summary:** Quick facts surfaced by the packed export and build.

- The Next.js build produced a generated Prisma Client; those generated artifacts are large and account for most tokens in a packed export.

- Routing groups present: `(auth)`, `(buyer)`, `(vendor)`, `admin`, and `signup` with nested pages and layouts.  
- A mock in-memory data implementation lives at `lib/data/database.ts` and is used by many endpoints for local development.
